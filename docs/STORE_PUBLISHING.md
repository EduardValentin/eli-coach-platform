# Store Publishing

The management API is the only supported way to put a product in the Store. It
runs inside the deployed app, so the same calls work on LOCAL, TEST, and PROD —
only the host and credential differ.

Never publish by writing PostgreSQL rows, copying files into the asset root, or
running an operational script. Those bypass format checks, size limits, taxonomy
validation, checksums, and the publication record.

## Routes

All require `Authorization: Bearer $MANAGEMENT_API_SECRET`, and HTTPS outside
LOCAL. The credential is checked before the body is read.

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/api/management/store/product-validations` | Dry run; persists nothing |
| POST | `/api/management/store/products` | Publish a new product |
| POST | `/api/management/store/products/{id}/versions` | Publish a content revision |
| POST | `/api/management/store/products/{id}/prices` | Change the prices, or turn paid↔free |
| PATCH | `/api/management/store/products/{id}` | Retire |

## Request

`multipart/form-data`, 25 MB total: a `metadata` JSON field, a `cover` image, and
one file per `metadata.downloads` entry, named by its `field`.

```jsonc
{
  "slug": "glute-growth-guide",  // new products only; immutable once published
  "idempotencyKey": "…",         // publishing routes only
  "title": "Glute Growth Guide",
  "creatorName": "Eli Lungu",
  "cardSummary": "…",            // <= 500 chars
  "detailDescription": "…",      // <= 10000 chars
  "includedItems": ["…"],        // 1..100
  "coverAlt": "…",
  "typeSlugs": ["e-books"],
  "goalSlugs": ["muscle-building"],
  "downloads": [{ "field": "file0", "customerFilename": "GluteGrowthGuide.pdf" }],
  "prices": { "eurCents": 3900, "usdCents": 4500 } // new products only; omit for a free product
}
```

Every object is strict: a field the route does not accept is rejected with
`400`, never ignored. `prices` on a content revision is such a field, because
prices change only through the price-change route.

**Prices**

- Amounts are whole minor units: `3900` is €39.00, `4500` is $45.00.
- A paid product carries both currencies; each amount is 1 … 99 999 999.
- One currency without the other (`missing_price`), a fraction
  (`price_not_whole_minor_units`), zero, a negative amount or one above the
  ceiling (`price_out_of_range`) is rejected, naming the currency.
- Without `prices` the product is free. The Store shows every price in the
  visitor's chosen currency, euros by default.

The dry run drops `idempotencyKey`. It needs either `slug`, to validate a new
product, or `targetProductSlug`, to validate a revision of an existing one; only
the new-product form accepts `prices`. It returns the publication plan — storage
keys, per-file MIME/size/SHA-256, resolved taxonomy, assigned order or sequence,
and the resolved `prices` (`null` for a free product, and always `null` for a revision, whose prices it does not change) — and writes nothing.

**Accepted values**

- Downloads: PDF, Markdown, EPUB, CSV, XLS, XLSX, XLSM, ZIP
- Covers: JPEG, PNG, WebP, AVIF
- Types: `workouts`, `nutrition-plans`, `e-books`
- Goals: `muscle-building`, `fat-loss`, `wellness`, `hormonal-balance`

Formats are decided from the bytes, not the filename or declared type; content
contradicting its extension is rejected. Taxonomy is fixed — an unknown value
comes back with the accepted list. Storage keys are derived server-side from the
content digest. Macro-enabled files are stored and delivered as opaque bytes and
never opened.

## Publishing

Covers are supplied, never generated by the app. To take one from a PDF's first
page (dev tooling; writes only an image):

```bash
pnpm --filter @eli-coach-platform/platform store:cover ./guide.pdf ./cover.webp
```

```bash
curl -sS -X POST "$APP_URL/api/management/store/products" \
  -H "Authorization: Bearer $MANAGEMENT_API_SECRET" \
  -F 'metadata={"slug":"glute-growth-guide","idempotencyKey":"b2d1c0f6-6f1a-4a2e-9c37-2f5f9a4c1d88","title":"Glute Growth Guide","creatorName":"Eli Lungu","cardSummary":"A practical guide to training the glutes with intent.","detailDescription":"Anatomy, exercise selection, and an example workout.","includedItems":["The three glute muscles and what each one does"],"coverAlt":"Cover of Glute Growth Guide.","typeSlugs":["e-books","workouts"],"goalSlugs":["muscle-building"],"downloads":[{"field":"file0","customerFilename":"GluteGrowthGuide.pdf"}]};type=application/json' \
  -F 'cover=@./cover.webp' \
  -F 'file0=@./GluteGrowthGuide.pdf'
```

Same body shape for the other routes: `product-validations` to dry-run,
`/{id}/versions` to revise (no `slug`, fresh key), `PATCH /{id}` to retire (no
body).

A revision becomes the latest version, keeps the product's catalog position, and
leaves already-issued grants pinned to their original version. Retirement stops
new acquisition while preserving history and existing owners' access; it is
idempotent.

## Changing prices

A price change is a JSON request, not multipart, and has no dry run. `prices`
is required, so making a product free is always explicit:

```bash
curl -sS -X POST "$APP_URL/api/management/store/products/42/prices" \
  -H "Authorization: Bearer $MANAGEMENT_API_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"idempotencyKey":"5c0e6a3e-1f0b-4d8e-a3f4-0a7b2c9d6e11","prices":{"eurCents":3900,"usdCents":4500}}'

curl -sS -X POST "$APP_URL/api/management/store/products/42/prices" \
  -H "Authorization: Bearer $MANAGEMENT_API_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"idempotencyKey":"9a4f2d71-3c6e-4b0a-8e15-6d2f7c1b0a93","prices":null}'
```

The first call makes product 42 paid (or reprices it); the second makes it
free. The product keeps its content version, its catalog position and every
download already granted, and moves between the Store's Plans and Free
resources sections. The publication record has the operation `reprice_product`
and `productVersionId: null`. A retired product (`product_retired`) and a
change to the same amounts or from free to free (`price_unchanged`) are
rejected.

Until paid products can be bought, the Store refuses a free-resource request
that includes a product that is paid at that moment; nothing is recorded or
sent. Publish paid products on TEST only once checkout exists.

## Idempotency

Replaying a key with the same payload returns the original publication with
`"replayed": true`; reusing it with a different payload is rejected. The key is
settled before validation, so retrying a request that already succeeded replays
it rather than failing on the slug it created.

## Responses

| Status | Meaning |
| --- | --- |
| `200` | Dry run, replay, or retirement |
| `201` | Published |
| `400` | Rejected payload — `error.issues` says which rule |
| `401` / `403` | Bad credential / not permitted or plaintext transport |
| `404` | Unknown product |
| `409` | Key reused with a different payload |
| `413` | Over 25 MB |
| `503` | Database, filesystem, or auth provider unavailable |

Failures publish nothing and leave no partial product visible.
