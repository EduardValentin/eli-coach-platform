Boundaries are enforced by four tools. `tools/dependency-cruiser.config.cjs` declares the path rules for the bounded-context layout — another bounded context reached only through its published folders (`bounded-context-imports-published-only`), schema foreign keys pointing at providers, sibling reads through published folders only, cross-context reads through the provider adapter and the bounded context's `public/` only, `ui/` and inbound HTTP reads of other bounded contexts, request-context key consumers, the compositions imported only from the level above, `domain/` importing only itself, the bounded context's facade folder importing no `domain/`, no cross-context `domain/` import, database types only in persistence and compositions, shared importing no bounded context, surface-to-bounded-context and surface-to-surface, the composition root, browser half, route thinness, the feature-flag override folder's single importer, a component's shared UI never importing its own actor UI, the browser-only design system, the design system's layering, a bounded context's `shared/` importing no component, vendor confinement (Clerk, Stripe in the sales shared payments and each sales component's payments adapter, Resend, `sharp`, `react-dnd`, pdf rendering, `@fastify/busboy`, `file-type`) and the hygiene rules — `tools/no-cycles.mjs` fails on a dependency cycle between bounded contexts or between components, so the dependencies form a directed acyclic graph whose direction no list fixes, `knip.json` holds published surfaces at zero unused exports, files, dependencies and unlisted dependencies, and `tools/domain-layout.mjs` checks every `domain/`'s per-entity folder layout and that no `shared/` folder holds a `domain/` or `adapters/`. All four run in `pnpm check:boundaries`, directly inside `pnpm validate` and the Docker builder stage, so a crossing fails workspace validation and image builds. `tools/boundaries.test.mjs` proves every dependency-cruiser rule against `tools/boundary-fixtures/`, one fixture that trips and one that passes per rule, each generated family proven once at family level. `tools/domain-layout.test.mjs` exercises `tools/domain-layout.mjs` against `tools/domain-layout-fixtures/` and against the real tree, and `tools/no-cycles.test.mjs` proves `tools/no-cycles.mjs` against `tools/no-cycles-fixtures/`, one tree that trips and one that passes for a bounded-context cycle, a component cycle and a component cycle through facades. Two rules stay review-owned by decision: controller shape (no base controller, no per-request instance field) and failure mapping (an adapter never swallows an infrastructure failure into a result-union member; a named expected condition may be classified and everything else is rethrown). The classified conditions are ENOENT in the filesystem asset store; ENOENT in the encrypted client media store (a missing photo or avatar opens as nothing and deletes as a no-op) and EEXIST on a folder it creates; Postgres `22P02` in the assessment-call repository (a malformed booking id is a mistyped URL) and Postgres `23P01` on the `coach_time_reservations_no_overlap` exclusion constraint in C23's `PostgresCoachTimeReservationsRepository.reserve` (losing a race for the coach's time is a taken slot), both read through C2's `isCausedByDatabaseError`; the waitlist signup's unique and check violations on its three named constraints, which register at the regular price or refresh consent; an insert that does nothing on `clients_assessment_call_id_unique` in the clients admitted-clients repository (a second payment for one call, answered `call_already_paid`), Postgres `23505` on `clients_auth_subject_id_unique` in the invited-clients repository (a lost acceptance race); Postgres `23505` on `client_onboarding_submissions_client_id_unique` in the client onboardings repository (a second submission is `already-submitted`) and on the partial `client_onboarding_detail_requests_open_per_client_unique` in the onboarding reviews repository (a request while one is open answers `not-in-review`); in the Clerk identity adapter, a revoke answered 404, or 400 with `invitation_revoked`, `invitation_already_revoked` or `invitation_cannot_be_revoked_code` (the earlier invitation is already settled, so the replacement goes on); in the Stripe adapters, a missing checkout session, an already-closed session on expiry, and an unverifiable webhook signature or body; and, in the progress-photo renditions adapter, any throw from `sharp` while reading or re-encoding an upload, answered `refused` like a format outside JPEG, PNG and WebP. Each is recorded in `decisions.md`. The dependency graph has no cycles at module, component, bounded-context or design-system-folder level. Deployment adds artifact controls outside the dependency rules: the platform package's `files` allowlist emits only `build`, and the Docker builder asserts that the deployed artifact contains `build/server/index.js`, has no top-level `src`, `e2e` or `test-support`, and holds no test or spec file outside `node_modules`. `tools/check-deploy-resolves.mjs`, proven by `tools/check-deploy-resolves.test.mjs`, resolves every bare import of every emitted server module under `build/server/` (the entry, the PDF worker and the renderer chunk the worker imports) from the `pnpm --prod deploy` layout, in the Docker builder and in `pnpm check:deploy`, the last step of `pnpm validate`; a vendor the adapters import (`@clerk/backend`, `stripe`, `sharp`) is declared by the platform package. Environment, Docker, CI, integration and Lighthouse wiring no longer carry `WAITLIST_MODE`; the seed folder `apps/platform/db/seeds/` inserts the persisted flag true after every migrate, and the Playwright suite leaves it alone, taking bookings out of waiting-list mode per browser through the public `ff.WAITLIST_MODE=false` override.

## Reading this folder

- `architecture.json`: the whole model: the components with their path globs and classification, the ports with their owners and humble sides, shared data shapes, and cohesion groups. Edited only through `arch model`; `arch model explain <path>` prints how a path is classified.
- `current.md`: the counts, the metrics per component and the component graph. Rewritten whole by `arch collect`.
- `tools/arch-adapter/`: the adapter that prints the dependency facts both commands read, over dependency-cruiser and the TypeScript compiler, with `tsconfig.architecture.json` at the repository root.
- `decisions.md`: deferred decisions, why each cohesion group exists, cohesion position per component, intended exceptions, open questions.
- `conventions.md`: where a file goes and what it may import; the folder layout the dependency rules assume.

Terms: a *unit* is a class, module, function, interface, or data structure. A *component* is a group of units behind one published interface that tooling enforces. An *edge* from A to B means A's source code names B. *Policy* is business rules; *detail* is databases, frameworks, transports, vendors, UI, and the data shapes they produce. A *ring* is a band of units at one level of distance from inputs and outputs; dependencies point inward.
