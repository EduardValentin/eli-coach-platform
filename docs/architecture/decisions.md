## Open questions

- Should `primitives` split further, given most consumers import one of its ten exports?
- Should the closed/unavailable/open copy branch move onto `WaitlistPresentation` if a fourth mode or a fourth consumer arrives?
- Payments: Stripe confirmed, no port or adapter exists; auth: Clerk confirmed and named directly in C9/C15; email: Resend in use behind B241.
- Should a feature's Turnstile action constant live in its own `contracts/` rather than in `packages/infrastructure/src/bot-detection/bot-detection-contract.ts`? C6 now names three actions (`WAITLIST_TURNSTILE_ACTION`, `STORE_ACQUISITION_TURNSTILE_ACTION`, `ASSESSMENT_CALL_BOOKING_TURNSTILE_ACTION`), one per protected form, so the adapter package carries a list that grows with the features rather than with the provider. The counter-argument is that the action string is part of the Turnstile submission contract, which is C6's to own. Deliberately deferred: if it moves, it moves as one mechanical follow-up across all three features, not piecemeal in GEN-191.
- `contracts/` now holds code as well as wire data: `assessment-calls/contracts/call-moment.ts` is a formatter, placed there because `contracts/` is the one browser-safe folder a feature's server half and browser half may both import. `conventions.md` records the widened folder. The consequence is that `feature-internals` and the three `surface-<s>-to-feature` rules treat the formatter as published, so any feature or surface may import it. Nothing does today. Should a feature have a browser-safe shared folder that is not published?
- Wider observation outside scope: `designs/react-reference-app` duplicates domain vocabulary (bundles, cycle phases) that C1 also declares; no shared source exists by design. GEN-191 extended that duplication: the prototype's `assessmentCallService.ts` re-declares the duration, buffer, step, horizon and lead-time literals that `ASSESSMENT_CALL_RULES` owns, because the prototype sits outside the pnpm workspace.

## Owner decisions (2026-09-16)

Every item in this block landed in `148d594f..871196af`.

- Single-coach platform for its lifetime. The model stays single-tenant; no owning-coach references are introduced. (This answers the run-1 "single-coach or multi-coach" question, which is removed from the deferred table.)
- Fix rather than accept: CH-M (explicit `BOT_DETECTION_PROVIDER`), F79 (dependency-cruiser and knip as typecheck and build gates), CH-S (domain-owned ports carry domain names; "repository" names an adapter), CH-K (six unused UI primitives removed, UI barrel split by concern).
- No TypeScript project references: pnpm's per-package resolution already fails an undeclared package edge at typecheck and build.
- knip joins dependency-cruiser for published-surface hygiene (unused exports, files, dependencies).
- R3 widens by one entry: `server/guards/` is a feature's surface-facing entry (context key and access guards). The cross-feature protocol is recorded in `dependencies.md`.
- Route thinness (F85) is enforced by the `route-thinness` dependency rule instead of review.
- `PUBLIC_APP_URL` is required in every runtime (previously required only with the Resend provider) because surfaces and Clerk session checks read it unconditionally.

Adopted from the architecture plan review of 2026-09-18 (verdict SHOULD_CHANGE on revision 1; the full disposition is in the implementation plan, section 11):

- **CH-F, adopted.** The waiting-list gate executes in the use cases, not the controller. `BookAssessmentCallUseCase` and `ListOpenSlotsUseCase` each hold a `bookingOpen` boolean and answer `closed`; the controller only turns `closed` into a 404. The container computes it once as `!environment.WAITLIST_MODE`.
- **CH-G, adopted.** The calendar is its own `packages/ui` subpath, `./calendar`, rather than a member of `primitives/`.
- **CH-A** moved the bot-detection config into the feature's composition so the booking loader reads only `assessmentCallsContext` and never the app's own `server/guards/`. **CH-B** made `EmailAttachment.content` a `Uint8Array`, leaving encoding to the Resend adapter. **CH-C** put the reservation ladder on `AssessmentCall.decideReservation`, called inside the repository transaction. **CH-D** kept `Date` on the snapshot and serialises once in the controller. **CH-E** gave `ListOpenSlotsUseCase` a three-member result so the use case, not the controller, decides that slots are unavailable. **CH-H** made `ASSESSMENT_CALL_RULES` the one home of the timing literals. **CH-I** is this record update.

**Two corrections to the approved plan, applied against the code rather than the plan.** The plan's revision 3 assumed `packages/ui` and `apps/platform` would both declare `date-fns` and `@date-fns/tz`. They do not. `react-day-picker` 9 converts `today`, `month`, `selected`, `disabled` and `modifiers` into the display zone itself through `TZDate`, so `packages/ui` declares `react-day-picker` alone; `apps/platform` declares `@date-fns/tz` alone, named by `ui/public/book/slot-grouping.ts` and nothing else, and the now-unused `date-fns` catalog entry was removed from `pnpm-workspace.yaml`. The split the record therefore states is: **zone arithmetic in the domain is `Intl`-only with no dependencies at all (`packages/domain/src/coach-availability/zoned-time.ts`); display-side zone handling uses `@date-fns/tz`'s `TZDate` to regroup instants into days plus `Intl` to label them.** The second correction is the wire time-zone validator: it does not use `Intl.supportedValuesOf`, whose list is canonical-only and omits `UTC`, `Etc/UTC` and `GMT`, which browsers really report. `contracts/assessment-calls.ts` accepts any string of at most 64 characters, the column's own width, that `new Intl.DateTimeFormat(undefined, { timeZone })` constructs without throwing. The result is not memoised: a process-lifetime cache keyed by unvalidated request input is an unbounded heap on a public endpoint, and there is nothing to amortise at one zone per request.

**Deploy contract change.** `ASSESSMENT_CALL_MEETING_LINK` and `ASSESSMENT_CALL_COACH_EMAIL` must be set in the TEST and PROD env files, which `terraform-infra` owns, before the next deploy.
